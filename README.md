# yolped

Deploy projects without leaving your terminal.

`yolped` is a CLI tool that manages Docker and Docker Compose deployments — set up a project once, then build, push, and deploy with a single command. Supports both local and remote (SSH) deployments with optional registry-based image distribution.

## Install

**With cargo (Rust users):**
```bash
cargo install yolped
```

**With curl (macOS / Linux):**
```bash
curl -fsSL https://raw.githubusercontent.com/quriousprof/yolped/main/install.sh | sh
```

Both install the `yolped` binary to a directory on your `$PATH`.

## Quick Start

```bash
# In your project directory
yolped setup              # create yolped.json, detect remote platform
yolped setup registry     # configure image registry (GHCR, Docker Hub, etc.)

yolped build              # build images
yolped push               # build + push to registry
yolped deploy             # deploy to configured server

# Or do it all in one step
yolped up
yolped up --version 1.2.0  # tag this release
```

## Commands

| Command | Description |
|---|---|
| `yolped setup` | Interactively create `yolped.json`, auto-detects docker file, detects remote platform |
| `yolped setup server` | Reconfigure only the server settings |
| `yolped setup registry` | Configure the image registry to push to |
| `yolped build` | Build images defined in `build.files` (or `deploy.file` as fallback) |
| `yolped push` | Build and push images to the configured registry |
| `yolped push --tag v1.2.3` | Push with an extra tag |
| `yolped push --version 1.2.3` | Override `@version` in configured tags for this push |
| `yolped deploy` | Deploy to the configured server (pull from registry if configured, else build on remote) |
| `yolped deploy --down` | Stop and remove running containers |
| `yolped deploy --rebuild` | Remove existing images and force a clean re-pull/rebuild |
| `yolped deploy --local` | Force local deployment, ignoring server config |
| `yolped up` | Build → push → deploy in one step |
| `yolped up --version 1.2.3` | Tag this release and run the full pipeline |
| `yolped logs [name]` | Stream logs for the current project or a named deployment |
| `yolped list` | List all registered deployments grouped by status |
| `yolped ssh` | Open an interactive SSH session to the configured remote server |

## Configuration

`yolped.json` lives in your project root and is generated by `yolped setup`. Edit it directly — all commands read it fresh on every run.

```json
{
  "name": "myapp",
  "version": "1.0.0",
  "build": {
    "files": [
      {
        "file": "services/api/Dockerfile",
        "image": "ghcr.io/user/myapp-api",
        "build_args": { "NODE_VERSION": "20" }
      },
      {
        "file": "services/web/Dockerfile",
        "image": "ghcr.io/user/myapp-web"
      }
    ],
    "platform": "linux/amd64"
  },
  "deploy": {
    "file": "docker-compose.yml",
    "args": ["--remove-orphans"]
  },
  "registry": {
    "tags": ["latest", "@version"]
  },
  "server": {
    "host": "203.0.113.10",
    "user": "ubuntu",
    "auth": "Password",
    "remote_dir": "~/deployments"
  }
}
```

### Fields

**`name`** — deployment name, used as the Docker container/image name locally.

**`version`** — project version string. Referenced in registry tags via `@version` (see [Versioned Tags](#versioned-tags)).

**`build`** — controls what gets built.
- `files` — array of Dockerfiles to build and push. Each entry supports:
  - `file` — path to the Dockerfile
  - `image` — fully qualified image name (e.g. `ghcr.io/user/myapp`). Falls back to `registry.image` if omitted.
  - `build_args` — key/value map of `--build-arg` values passed to Docker
- `platform` — target platform for cross-compilation (e.g. `linux/amd64`, `linux/arm64`). Auto-detected from the remote server during `yolped setup` and used with `docker buildx build --load`.

**`deploy`** — controls what runs on the server.
- `file` — Dockerfile or `docker-compose.yml` to run. Used by `deploy`, `logs`, `stop`, and `ssh`.
- `args` — extra flags forwarded to `docker run` or `docker compose up`.

**`registry`** — where to push images.
- `image` — fallback image name used when a `build.files` entry has no `image` field.
- `tags` — tags to push. Supports `@version` placeholder.

**`server`** — remote server over SSH (omit for local-only deployments).
- `host` — hostname or IP address
- `user` — SSH user
- `auth` — `"Password"` (prompted at runtime, never stored) or `{ "Key": "/path/to/key" }`
- `remote_dir` — directory on the server to upload files to

## Versioned Tags

Set a `version` in `yolped.json` and use `@version` in your `registry.tags`:

```json
{
  "version": "1.4.2",
  "registry": {
    "tags": ["latest", "@version"]
  }
}
```

`yolped push` resolves `@version` → `1.4.2` and pushes both `latest` and `1.4.2`.

Override for a single run without editing the file:

```bash
yolped push --version 2.0.0
yolped up   --version 2.0.0
```

## Setup Wizard

`yolped setup` walks through:

1. Deployment name (auto-generated default)
2. Project directory (defaults to current)
3. Auto-detect Dockerfile / docker-compose file, or enter a custom path
4. Server — Local (default) or Remote
   - If Remote: host, SSH user, auth method (password or key file with **tab-completion**)
   - Connects to the server and auto-detects the CPU architecture, storing it in `build.platform`

Re-running `yolped setup` backs up the existing config to `yolped.json.old` before overwriting.

## Remote Deployments

### Registry-based (recommended)

1. `yolped setup` → choose Remote, enter server details
2. `yolped setup registry` → enter image name(s) and tags
3. `yolped up` — builds images locally (with `buildx` for cross-compilation), pushes to registry, connects to server and runs `docker pull` + `docker run` / `docker compose pull` + `docker compose up -d`

No Docker build tools are needed on the server — it only needs Docker to pull and run.

### Build-on-remote (no registry)

If no registry is configured, `yolped deploy` will:

1. Connect over SSH
2. Upload your `docker-compose.yml` or `Dockerfile`
3. Handle missing env files (prompts to copy local ones)
4. Build the image directly on the server (using the detected `build.platform`)
5. Run the container, streaming all output to your terminal

## Registry

`yolped` tracks registered projects in `~/.yolped/registry.json`. Only the path to each `yolped.json` is stored — no config is duplicated. `yolped list` does a live Docker status check on every entry.
